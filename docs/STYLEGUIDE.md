# StudyOnTV UI 设计规范（Style Guide）

> 借鉴自 `stablyai/orca/docs/STYLEGUIDE.md`，围绕 StudyOnTV 的三大界面（`parent-ui/` 家长面板、`app/web/` TV/平板学习页、`app/native/parent/` 原生家长端 App）定制。
> 视觉 Token 数值的唯一真相源在 [`parent-ui/src/theme.css`](../parent-ui/src/theme.css)；本文档约定**角色与规则**，不重复抄录具体色值。

## 核心气质：单色克制，清晰可读

家长端面对的是家庭日常高频微操作（出题、看进度、改规则、远程解锁），界面应**克制、安静、零干扰**：

- **中性灰阶承载骨架，彩色只留给状态与唯一主操作**。
- 拿不准时按以下顺序做决定：
  1. 先用 **muted / accent / border**，不要急着加彩色；
  2. 先用 **CSS 变量 Token**，禁止在组件里手写 hex；
  3. 先复用 **`parent-ui/src/components/ui/`** 里的 shadcn 原语，再考虑写自定义样式。

## 颜色与 Token 规则

- 颜色必须以 **表面（surface）+ 前景（foreground）** 成对使用，确保浅色与深色模式都满足对比度：
  - `background`：页面底布；`card`：抬起的卡片面板；`popover`：悬浮菜单与弹窗；`input`：仅用于表单控件边框/底色。
  - `primary`（全站唯一蓝色强调色）：**仅用于当前流程中唯一的主确认操作**，不用于装饰性徽章、普通悬停或次级按钮。
  - `secondary`：同级次要按钮；`accent`：ghost 按钮与列表行悬停/激活底色，不用于实心大按钮。
  - `muted-foreground`：辅助说明、次要元数据、占位文字，不用于正文主体。
  - `destructive`：删除、清空、不可逆操作与错误态；**绝不用于「取消 / 返回 / 关闭」**。
  - `border`：1px 发丝分割线；`ring`：仅用于键盘/遥控器 `focus-visible` 焦点环，不做常驻装饰边。
- 需要浅色底或微调色阶时，优先用 `color-mix(in srgb, var(--token) N%, var(--background))` 基于现有 Token 派生，自动保证浅/深色对称；禁止为了一个卡片新建一次性 hex 色值。
- 新增 Token 时必须在 `theme.css` 的 `:root`、`.dark` 和 `@theme inline` 三处同时登记。

## 排版与密度

- 常规正文 `14px`，侧边栏与密集列表行 `13px`，次要元数据 `12px`，微标 `11px`；数字与倒计时统一 `tabular-nums` 防跳动。
- 圆角遵循全站基准（见 `theme.css`）：常规控件（按钮/输入框/下拉）`4px`–`8px`，卡片与弹窗容器 `8px`–`12px`，避免过度夸张的大圆角泡感。
- 图标统一使用 `lucide-react`（默认 `size-4`、继承文字颜色），加载态统一 `<Loader2 className="size-4 animate-spin" />`。

## 交互与文案纪律（UX Rules）

每项 UI 改动都必须满足以下 UX 规则：

1. **文案不越界、不废话**：
   - 未拿到真实结果或状态前，不要暗示已经完成（进行中用中性动词，如「正在连接」「推送中」；拿到结果后再用「已开启」「已跳过」「已完成」）。
   - 面向家长的文案说人话，去掉「请您」「只需」「简单地」等填充词，尽量不暴露底层技术术语（如把 `GET_USAGE_STATS` 写清为「应用使用情况权限」）。
2. **按耗时分级给反馈**：
   - `0–100 ms`：直接出结果，不闪加载态；
   - `100 ms–1 s`：禁用触发按钮防连点；
   - `1–3 s`：禁用按钮 + 加载指示器（尽量延迟 ~200 ms 展示避免本地瞬间完成时闪烁，并预留宽度防止按钮跳动）；
   - `3 s+` 或多步流程（如导入文档、下载/推送 APK、无线 ADB 配置）：必须展示**分步骤实时状态与百分比进度**。
3. **退出路径保持安静**：
   - 「取消 / 关闭 / 返回 / 跳过」一律使用无色 ghost 或安静次级样式，不标红、不抢主操作焦点；弹窗支持 `Esc` / 返回键退出。
4. **缺数据时给直达行动**：
   - 空状态、离线态或权限缺失时，不干巴巴只报「暂无数据 / 连接失败」，必须紧跟 1–2 个可直接点击的下一步操作（如「重试连接」「去无线 ADB 修权限」「手动添加 IP」）。
   - 短暂结果用 Toast；需要家长阅读、复制或重试的持久错误必须内联展示在页面里。
5. **同流组件保持一致**：
   - 同一页面的相邻表单项、弹窗与列表卡片共享一致的图标风格、按钮顺序（左次右主）和提交语义。
   - 折叠区块的箭头统一放在标题之前或整行最右侧，同组不混用。

## 多端适配要求

- **触屏与桌面兼顾（`parent-ui/`）**：只在桌面悬停才显露的操作按钮，必须使用 `@custom-variant can-hover` 包裹，确保在手机/平板浏览器与家长端 WebView 里始终可见可点；移动端输入框字号不小于 `16px` 防止 iOS 自动放大。
- **电视 10 英尺体验（`app/web/`）**：所有可交互元素支持方向键线性移动与高对比焦点环，远距可读，不依赖悬停与精细点击；严禁使用 ES6+ 语法。
- **原生家长端 App（`app/native/parent/`）**：配色与层级对齐 `parent-ui/src/theme.css`——浅色背景 `#FAFAFB` / 卡片 `#FFFFFF` / 发丝边框 `#E4E7EC` / 唯一蓝主操作 `#2563EB`（深色背景 `#111318` / 卡片 `#191D24` / 边框 `#2A303B` / 主蓝 `#60A5FA`），确保从原生设备列表进入 WebView 家长面板时视觉风格连贯统一。
